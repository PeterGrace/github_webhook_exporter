# Version-Tag Image and Helm Chart Publication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish one immutable `linux/amd64` image and one validated Helm OCI chart from canonical stable version tags, with digest-verified chart-only recovery after a partial release.

**Architecture:** Keep the existing `validate` job as the only producer of releasable artifacts, then pass its exact chart archive to one tag-gated `publish-release` job. A repository-owned Bash helper inspects both GHCR targets and implements a fail-closed state machine; it permits chart-only recovery only when the remote image configuration digest equals the rebuilt local image ID.

**Tech Stack:** GitHub Actions, GHCR, Docker/Buildx, Helm OCI, Bash, Python-backed `yq` workflow contract tests, Cargo and Helm metadata.

## Global Constraints

- Pull requests and `main` are validation-only and must never authenticate to or push into GHCR.
- Temporary GitHub Actions chart artifacts remain available for 30 days.
- Publication accepts only canonical `vMAJOR.MINOR.PATCH` tags; each numeric component forbids leading zeroes except for zero itself.
- The normalized tag, Cargo package version, Helm chart version, and Helm `appVersion` must match exactly before authentication.
- Publish only `ghcr.io/petergrace/github-webhook-exporter:MAJOR.MINOR.PATCH` for `linux/amd64` and `oci://ghcr.io/petergrace/charts/github-webhook-exporter --version MAJOR.MINOR.PATCH`.
- Never create mutable `latest`, branch, SHA, or prerelease tags.
- Use only the workflow-scoped `GITHUB_TOKEN`; the publication job alone receives `contents: read` and `packages: write`.
- Every third-party GitHub Action must be pinned to a full commit digest.
- All chart and image validation must finish before authentication and before either push command.
- No existing image or chart may be overwritten.
- Chart-only recovery requires a missing chart and exact equality between the remote image configuration digest and local Docker image ID.
- Remote inspection errors must fail closed and must never be interpreted as confirmed absence.
