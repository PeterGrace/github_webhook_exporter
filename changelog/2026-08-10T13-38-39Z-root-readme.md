# Root README

## Problem

The repository had no `README.md`. Anyone landing on the project saw a file listing and no
statement of what the service does, how to run it, or where the real documentation lives.

## Change

Added a root `README.md` as the project entry point: what the exporter does, a container quick
start, Helm install, configuration, HTTP endpoints, metric names, development commands, and a
documentation map.

Two deliberate boundaries:

- **Helm values are not duplicated.** `charts/github-webhook-exporter/README.md` already documents
  all 66 keys in `values.yaml` with defaults and constraints. The root README carries a
  fourteen-row map of value *groups* and points at the chart README as authoritative. Copying the
  full table would recreate the version-drift failure fixed in
  [2026-08-10T11-14-38Z-pr-gated-release-flow.md](2026-08-10T11-14-38Z-pr-gated-release-flow.md).
- **The environment variable reference is new, not copied.** `docs/operations.md` documented only
  the three required variables plus three OTLP queue settings. The complete set of 24 variables read
  by `src/config.rs` was not collected anywhere, so the root README is now its home.

The two pinned versions in the quick start are registered in `pre-release-replacements`, so
`cargo release` keeps them in step with the crate, chart, chart README, and operations guide. A dry
run confirms all four files are rewritten.

## Verification

- `just workflow-test`, `just helm-static` pass.
- `cargo metadata` parses the extended `pre-release-replacements`.
- Every relative link in the README resolves.
- Endpoint paths, environment variable names and defaults, metric names, and the
  `CreateRepositoryRequest` JSON fields were read from `src/` rather than inferred.

## Files

- `README.md` — new.
- `Cargo.toml` — two `pre-release-replacements` entries for the README quick start.
- `docs/build-spec.md` — status banner strengthened; six divergences flagged inline.

## Stale build spec

`docs/build-spec.md` contradicted the implementation in six places. It was neither deleted nor
moved: two changelog entries and the superseding design document all link to it, so removing or
relocating it would break those references and discard a cited record.

Instead its status banner now states plainly that it is not a reference for the running service and
points at `README.md` and `docs/operations.md`, and each divergence is flagged inline. The original
text is left as written — this is a record of what was planned, and correcting it in place would
misrepresent that.

Flagged divergences:

| Location | Divergence |
| --- | --- |
| Configuration API | Authenticates with `GHE_ADMIN_TOKEN`, not the master key. |
| Security, master key | Only the key-derivation use was built. |
| Prometheus metrics | Lists ten of fifteen registered instruments. |
| Bounded labels | Implemented `stage` values are `authentication`, `delivery_claim`, `metrics`, `database`, `queue_state`; there is no `telemetry` stage. |
| OpenTelemetry spans | Omits `retention.run`, `github.workflow.job`, `github.workflow.step`. |
| Kubernetes operation | The Secret must also supply `GHE_ADMIN_TOKEN`, or startup fails. |

Sections reviewed and found consistent with the code: architecture, webhook endpoint and its status
codes, SQLite data model, event processing, and acceptance criteria.
